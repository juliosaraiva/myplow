# Offline A/B/C notification evaluation

`tools/learning_eval.py` runs three fresh subprocesses per arm and incident. Give it synthetic development input or have the independent reviewer run sealed holdout input privately. Neither labels nor resolved trajectories enter `run`. It rejects unknown input fields. Only C receives a frozen private copy of the approved development SQLite snapshot. Keep snapshot and results outside source control.

`python tools/learning_eval.py run CASES.jsonl APPROVED.sqlite3 TRACES.jsonl --evaluator-sha SHA` requires a clean committed checkout, writes a new file and randomizes arm order within each repetition. Each JSONL input row has `incident`, integer frozen epoch second `at`, `facts`, currently `active_policy` (an action or null), and `budgets`. The fact fields are `repo`, `role`, `event`, `event_id`, `observed`, `exceptions`, `available`, `verified`, `authorized`, `recipients` (opaque `owner` and `worker` IDs or null), and `prior_attempts` (recipient roles already attempted for this event). Budgets are integer `context_bytes`, `calls` and `tool_calls`. IDs are opaque synthetic 32-character hex identifiers.

A projects verified synthetic merges and reviews into the current supervisor ledger's action producer. Other events without a corresponding supervisor path have no A action. B is a fixed notification rule. C consults eligible lessons and falls back to A when none applies. All arms obey the same explicit policy, access checks and budgets. The worker is deterministic code in a fresh process with a fresh directory and empty credentials. There is no client, tool execution, remote model, or network dispatch. The parent collects framed attempted deliveries before scoring, including attempts that precede a worker crash or timeout and attempted deliveries with no destination. Trace counts must equal the attempt list. Promotion scoring requires every timing sample. Fresh processes prove session isolation. A distinct model-worker identity, billing measurements and generalization still require separate validation. The trace includes resource counters, duration, errors, the clean implementation SHA, specified evaluator SHA, and digests for the worker policy and consulted lessons. It deliberately leaves model cost unavailable.

Keep fitting, baseline selection and the holdout separate by incident group. Reviewers choose the strongest baseline on development only, with a tie selecting B, and freeze sample size before holdout. `python tools/learning_eval.py score TRACES.jsonl LABELS.jsonl --baseline B --minimum-incidents N` takes separate labels with `incident`, `action`, ordered `destinations` (role and opaque ID), full final `state` (sorted attempted roles and abstention), applicable `critical` categories, and optional `eligible_lessons` digest allowlist for scope-critical labels. Use `cross_scope`, `unauthorized_attempt`, and `mandatory_omission` where the label can identify these violations from the action trace. For scope-critical labels, populate the allowlist from the frozen development snapshot without giving it to workers. Missing allowlist means zero lesson digests are allowed for that label. Keep hidden labels and incident-level output private.

Score reports raw counts, paired corrections and degradations, three-of-three accuracy, incident-bootstrap lower 95% bound, latency p95, and CPU resource units. Promotion criteria are at least ten percentage points of gain, positive paired lower bound, zero critical violations, cost per correct at most 110% of baseline, p95 latency at most 115% with at most 250 ms added, and sufficient incident count. Missing metering means inconclusive. Deterministic development results cannot establish model-worker benefit, justify live activation, or verify provider delivery. B is the fallback until evidence supports C. No MLflow writes or shadow/canary activation.
